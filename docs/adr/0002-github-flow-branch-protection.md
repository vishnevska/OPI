# ADR-0002: Застосування GitHub Flow та захисту гілки main

Статус: прийнято

## Контекст
Під час розвитку проєкту існує ризик випадково завантажити неперевірений або зламаний код
(наприклад, із помилками кодування файлів) безпосередньо в основну робочу гілку.

## Рішення
Впровадити методологію розгалуження GitHub Flow: заборонити прямі коміти в гілку `main` через налаштування Branch
Protection Rule і дозволити додавання нового коду виключно через Pull Request із попереднім рецензуванням.

## Наслідки
- **Переваги:** Головна гілка `main` завжди залишається стабільною та робочою; кожна зміна проходить
-  перевірку перед злиттям; історія змін стає прозорою завдяки стратегії Squash and Merge.
- **Компроміси та обмеження:** Збільшується час на доставку навіть дрібних виправлень, оскільки замість
-  одного прямого `git push` потрібно створювати окрему гілку, відкривати PR та проходити процедуру злиття.
